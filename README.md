# وِكاد — ركن ضيافة القهوة
# Wekad — Coffee Catering Counter

موقع حجز خدمات كيترنق القهوة. العميل يختار الخدمة، ثم عدد الأكواب، ثم عدد الأيام،
ثم يحدد إن كان الحجز باسم شركة أو باسمه الشخصي — وينتهي بإرسال الطلب كاملاً
على واتساب.

---

## التشغيل

الموقع **ملفات ثابتة فقط**: لا يحتاج قاعدة بيانات ولا سيرفر ولا تنصيب أي شيء.

**للمعاينة على جهازك:**

```bash
npx --yes serve -l 4173 ~/Desktop/wekad
```

ثم افتح `http://localhost:4173`.

**للنشر:** ارفع محتويات المجلد كما هو على أي استضافة —
Netlify أو Vercel أو GitHub Pages أو أي استضافة cPanel عادية. ما فيه خطوة بناء.

## مسار الحجز

أربع خطوات فقط، وتبدأ ببيانات العميل حتى لا يضيع الطلب إن انسحب في منتصف الطريق:

```
1. بياناتك        →  الاسم، الجوال، أفراد أو شركة
2. الخدمة         →  ركن القهوة أو الحافظات + الحجم
                     (+ حلى وإضافات في قسم اختياري مطوي)
3. الموعد والموقع →  التركيب، بدء العمل، الأيام، المدينة، الحي، الخريطة
4. التأكيد        →  مراجعة ثم "تأكيد الطلب"
```

الصفحة الرئيسية خفيفة كذلك: الغلاف، نبذة، الباقات، ثم **الحجز مباشرة**. أقسام
الحافظات والخدمات الإضافية وقائمة الحلى أُزيلت من الصفحة — وما زالت متاحة داخل
نموذج الحجز نفسه ضمن القسم الاختياري.

**الحافظات بلا باريستا:** عند اختيارها يظهر للعميل أنها تُسلَّم جاهزة ومحفوظة
على حرارتها، ولا تُحتسب معها باريستا.

### الباقة المخصصة

إلى جانب الباقات الخمس، يجد العميل خياراً سادساً: **باقة مخصصة**. عند اختياره
تنفتح له لوحة يكتب فيها عدد الأكواب التقريبي ووصفاً لما يحتاجه (نوع المناسبة،
المشروبات، عدد الباريستا، أي تجهيزات خاصة).

الطلب يصل بعلامة واضحة في رسالة واتساب وفي لوحة التحكم، ويظهر للطاقم في بطاقة
المهمة ضمن صندوق **طلب خاص من العميل**. السعر يُعرض عليه يدوياً بعد المراجعة.

### الكميات والباريستا

كل صنف — إضافة أو حلى — له عدّاد مستقل، والعميل يحدد العدد اللي يبيه.

**الباريستا مشمولة مجاناً:**

- **باريستا واحدة** مع كل طلب، بدون رسوم.
- **باريستان** تلقائياً إذا كانت الباقة **٢٠٠ كوب فأكثر** *و* طلب الحلى
  **١٠٠٠ ر.س فأكثر**.
- أي باريستا زيادة على المشمول تُحسب **٣٠٠ ر.س لكل باريستا في اليوم**.

الحدود قابلة للتعديل من `BARISTA_RULE` في أعلى [app.js](assets/js/app.js):

```js
const BARISTA_RULE = {
  base: 1,                 // المشمول دائماً
  bonusFromCups: 200,      // الباقة "الكبيرة" تبدأ من هذا العدد
  bonusFromDesserts: 1000, // قيمة الحلى التي تُعتبر "كثيرة" (ر.س)
};
```

**باقي البنود:**

- **طباعة أكواب:** ٥ ر.س لكل كوب، تُطلب بخطوات من ٢٥.
- **التارت:** ٣٠٥ ر.س للطبق (٥٠ حبة) — كاسترد، بيكان، تشوكلت.
- **الكيك الطبيعي الكبير:** السعر للكيكة الواحدة —
  بيكان ٣٥.١ · قراهم ٣٧.٧ · جزر ٣٧.٧ · وِكاد تشيزكيك ٣٧.٧ ·
  وِكاد تشوكلت ٣٧.٧ · لندن ٤١.٦ · كلاسيك تشوكلت ٣٥.١ · ماتلدا ٤١.٦

### تحديد الموقع

العميل يختار المدينة (**المنطقة الشرقية فقط**) ويكتب الحي، ثم يحدد المكان بدقة
على خريطة تفاعلية — إما بسحب الدبوس أو بالضغط على الخريطة أو بزر
"موقعي الحالي". يصلك رابط خرائط Google جاهز مع الطلب.

الخريطة تعتمد على Leaflet و OpenStreetMap، بدون أي مفتاح API أو اشتراك.
لو تعذّر تحميلها لأي سبب، يظهر للعميل تنبيه ويكمل الطلب بوصف الموقع كتابةً.

> **الأسعار مخفية عن الموقع العام.** العميل يشوف الباقات والأصناف بلا أي مبلغ،
> ويصلك طلبه لتعرض عليه السعر بنفسك. الأسعار ما زالت محفوظة في الكود وتُحسب
> وتُخزَّن مع كل طلب، فتقارير الإيرادات في لوحة التحكم تعمل كالمعتاد.

## تعديل الأسعار والباقات

كل البيانات في أعلى ملف [assets/js/app.js](assets/js/app.js) — عدّل الأرقام واحفظ، خلاص:

```js
const WHATSAPP = '966552487363';        // رقم استقبال الطلبات

const PACKAGES = [ … ];                  // باقات ركن القهوة
const FLASKS   = [ … ];                  // خدمة الحافظات

const EXTRAS = [                         // الإضافات المدفوعة
  { id:'barista', price:300, per:'day',   step:1,  max:10   },
  { id:'print',   price:5,   per:'piece', step:25, max:3000 },
];

const BARISTA_RULE = { base:1, bonusFromCups:200, bonusFromDesserts:1000 };

const DESSERT_GROUPS = [                 // الحلى مجمّعة حسب وحدة البيع
  { id:'tart', ar:'التارت', note:'الطبق ٥٠ حبة', unitAr:'طبق', items:[ … ] },
  { id:'cake', ar:'الكيك الطبيعي الكبير', note:'السعر للكيكة الواحدة',
    unitAr:'كيكة', items:[ … ] },
];

const CITIES     = [ … ];                // مدن المنطقة الشرقية
const MAP_CENTER = [26.4207, 50.0888];   // مركز الخريطة الافتراضي
```

- `per: 'day'` → السعر × الكمية × عدد الأيام.
- `per: 'piece'` → السعر × الكمية (مرة واحدة).
- `step` → مقدار الزيادة عند الضغط على `+`.

لتغيير رقم الاستقبال: عدّل `WHATSAPP` في الملف أعلاه، وكذلك الروابط
في [index.html](index.html) (ابحث عن `966552487363`).

## التحليلات

الموقع يرسل أحداثاً جاهزة لـ **Google Analytics 4** و **Microsoft Clarity** — الاثنان مجانيان.
افتح [assets/js/analytics.js](assets/js/analytics.js) وضع المعرّفين في أول الملف:

```js
const GA4_ID     = '';   // G-XXXXXXXXXX
const CLARITY_ID = '';   // abcdefghij
```

ما دامت فاضية، الموقع يشتغل عادي والأحداث تُطبع في Console فقط.

### كيف تجيب المعرّفات

**Google Analytics** — [analytics.google.com](https://analytics.google.com) ← Admin ←
Create property ← اسم الموقع والمنطقة الزمنية ← Web ← اكتب `wekad.store` ←
ينطلع لك **Measurement ID** يبدأ بـ `G-`.

**Microsoft Clarity** — [clarity.microsoft.com](https://clarity.microsoft.com) ←
New project ← اكتب `wekad.store` ← من Settings انسخ **Project ID**.

### الأحداث المرسَلة

| الحدث | متى يُرسل | يحمل |
|---|---|---|
| `page_view` | فتح الموقع | تلقائي |
| `select_service` | اختيار ركن أو حافظات | نوع الخدمة |
| `begin_checkout` | أول تقدّم في نموذج الحجز | القيمة المبدئية |
| `booking_step` | كل خطوة | رقم الخطوة واسمها |
| `select_item` | اختيار باقة أو حافظة | الاسم والسعر |
| `add_to_cart` | أول إضافة لصنف حلى أو إضافة | الصنف والكمية والقيمة |
| `set_location` | تحديد الموقع على الخريطة | المدينة |
| `booking_error` | توقّف العميل بسبب حقل ناقص | الخطوة ونص الخطأ |
| `purchase` | تأكيد الطلب | رقم الطلب، الإجمالي، وكل الأصناف |

`purchase` بصيغة GA4 القياسية، فتقارير الإيرادات ومتوسط قيمة الطلب تشتغل تلقائياً
بدون أي إعداد إضافي.

### وين تشوف الأرقام

- **كم زائر ومن وين جاء وأي جهاز** → Analytics ← Reports ← Acquisition / Tech
- **وين يطلعون من الحجز** → Analytics ← Explore ← Funnel exploration،
  رتّب الخطوات: `begin_checkout` ثم `booking_step` ثم `purchase`
- **أي باقة وأي حلى الأكثر طلباً + متوسط قيمة الطلب** → Analytics ← Reports ←
  Monetization ← Ecommerce purchases
- **تسجيلات فيديو وخرائط حرارية** → Clarity ← Recordings / Heatmaps
- **الحقول اللي يتعثّرون فيها** → Analytics ← Events ← `booking_error`

> البيانات تبدأ تظهر خلال ٢٤ ساعة تقريباً في Analytics، وخلال ساعتين في Clarity.

## لوحة التحكم

`dashboard.html` — تدخلها ببريد وكلمة مرور من Supabase. لا يقدر أحد يفتحها بدون
حساب؛ قواعد الصلاحيات في قاعدة البيانات هي الحاجز، لا إخفاء الصفحة.

### الصفحات

اللوحة أربع صفحات، التنقّل بينها من القائمة الجانبية:

**نظرة عامة** — عشرون رقماً ثابتاً أمامك مباشرة: الإيرادات المؤكّدة، إجمالي
الطلبات، متوسط الطلب، نسبة التحويل، قيمة قيد الانتظار، أكبر طلب، الزوار،
الجلسات، من بدأ الحجز ومن أتمّه، الأكواب المباعة، مبيعات الحلى والإضافات،
متوسط مدة الخدمة والمهلة قبل المناسبة، المناسبات القادمة، ونسبة الشركات.
تحتها ثلاثة أقسام مطويّة تُفتح بزر **عرض**: الطلبات والزوار يومياً، مسار الحجز،
وحالات الطلبات.

**الطلبات** — الجدول الكامل: بحث، تصفية بالحالة وبالمدينة، فرز بأي عمود،
تصدير إكسل، وتحكم كامل بكل طلب (تغيير الحالة · إلغاء · حذف · عرض التفاصيل).
شارة حمراء في القائمة الجانبية تعدّ الطلبات الجديدة.

**التحليلات** — تسعة رسوم: مصادر الزوار، الأجهزة، الإيرادات شهرياً، الباقات
والحلى والإضافات الأكثر طلباً، المدن بالعدد وبالإيراد، وأيام المناسبات.

**الأيام المقفلة** — إقفال يوم أو مدى من الأيام مع سبب. اليوم المقفل يصير غير
متاح في بوابة الحجز فوراً: يظهر للعميل ضمن "أيام غير متاحة"، وإن اختاره يُرفض
برسالة تذكر السبب. الفتح بضغطة واحدة.

**المستخدمون** — إنشاء الحسابات وإدارة الصلاحيات.

المدى الزمني (٧ / ٣٠ / ٩٠ / الكل) في الشريط العلوي ويسري على كل الصفحات.

### اللغات

اللوحة بثلاث لغات: **العربية** (RTL) و**English** و**Filipino**. المبدّل في أعلى
الشاشة وفي صفحة الدخول.

المدير يحدّد لغة الموظف وقت إنشاء الحساب، والموظف يقدر يغيّرها بنفسه بعدها —
والاختيار يُحفظ في حسابه فيظهر على أي جهاز يدخل منه.

الترجمات في [assets/js/dash-i18n.js](assets/js/dash-i18n.js): العربية هي المرجع،
وأي مفتاح ناقص في لغة أخرى يرجع لها تلقائياً.

### الصلاحيات

صلاحيتان، والفرق بينهما **مفروض في قاعدة البيانات لا في الواجهة**:

| | المدير | الموظف |
|---|---|---|
| الطلبات بالتفصيل | ✅ | ❌ |
| الأسعار والإيرادات | ✅ | ❌ **لا تصله أصلاً** |
| تحليلات الزوار | ✅ | ❌ |
| جدول المناسبات القادمة | ✅ | ✅ |
| موعد التركيب ووقت الوصول | ✅ | ✅ |
| بدء العمل · المدينة · الموقع · الخريطة | ✅ | ✅ |
| اسم العميل وجواله وملاحظاته | ✅ | ✅ |
| تغيير حالة الطلب · الإلغاء · الحذف | ✅ | ❌ |
| إدارة المستخدمين | ✅ | ❌ |
| تصدير إكسل | ✅ | ❌ |

الموظف يقرأ من عرض `schedule` — وهو **لا يحتوي أي عمود سعر من الأساس**، وأسعار
الأصناف مُزالة من داخل الـ JSON. حتى لو فتح أدوات المطوّر أو نادى الواجهة
البرمجية مباشرة، الأرقام المالية غير موجودة في الرد. وجدول `orders` نفسه
مقصور على المدير بقاعدة صلاحيات.

### إضافة موظف

من اللوحة: **المستخدمون والصلاحيات** ← اكتب بريده ← **توليد** كلمة مرور (أو اكتبها
بنفسك) ← اختر الصلاحية ← **إنشاء الحساب**.

يُنشأ الحساب فوراً، وتظهر لك البيانات لتعطيها للموظف. يفتح `dashboard.html`
ويدخل بها مباشرة — لا تسجيل ولا بريد تفعيل.

> يتطلب تعطيل **Confirm email** من Supabase ← Authentication ← Sign In / Providers
> ← Email. اللوحة تنبّهك إن كان ما زال مفعّلاً.

### قائمة التجهيز

قبل الخروج للموقع، يعلّم الموظف ما أخذه معه. القائمة تظهر داخل بطاقة كل مهمة
مع عدّاد (`٣ من ٨`)، وتتحوّل إلى **جاهز للخروج ✓** عند اكتمالها. كل علامة
تُحفظ مع **اسم من علّمها ووقتها**، فالتقدّم مشترك بين كل من يفتح نفس المهمة.

**البنود بوحدات وكميات:** كل بند يحمل وحدة اختيارية — كجم · حبة · لتر · علبة ·
كرتون · كيس — وكمية افتراضية. البنود ذات الوحدة تظهر للعامل بخانة رقم يعدّلها
بالكمية التي أخذها فعلاً (القهوة بالكيلو، الأكواب بالعدد)، والبنود بلا وحدة
تُعلَّم فقط.

**تحكم كامل للمدير** من صفحة **قائمة التجهيز**:

| العملية | كيف |
|---|---|
| إضافة بند | النموذج العلوي: الاسم بثلاث لغات + الوحدة + الكمية الافتراضية |
| تعديل أي بند | زر **تعديل** — يفتح الصف للتحرير: الأسماء والوحدة والكمية |
| إعادة الترتيب | أسهم ↑ ↓ |
| الحذف | زر **حذف** مع تأكيد |

### حالة المهمة

الطاقم يحدّد أين وصلت المهمة من البطاقة نفسها:

```
لم يبدأ  →  خرجنا  →  وصلنا  →  ركّبنا  →  انتهينا
```

المرحلة الحالية بارزة، والمنجزة تحمل علامة ✓، ويظهر تحتها **من غيّرها ومتى**.
التغيير يُسجَّل في الطلب فيراه المدير ويرى بقية الطاقم. الموظف لا يملك صلاحية
الكتابة على جدول الطلبات مباشرة؛ التغيير يمرّ عبر دالة محمية تتحقق من أنه
ضمن الطاقم.

### شاشة الموظف

بطاقة لكل تركيب، مرتّبة بالأقرب، ومصمّمة للقراءة من الجوال في الموقع:

- **وقت الوصول للتركيب** بأكبر خط في البطاقة
- شريط جانبي ملوّن حسب القرب: **أحمر لليوم · برتقالي للغد** · أخضر لما بعدها،
  مع كلمة صريحة (اليوم / غداً / بعد ٣ أيام) فاللون لا يحمل المعنى وحده
- المدينة والحي ومكان المناسبة والخدمة المطلوبة وعدد الباريستا والأصناف
- ملاحظة العميل في صندوق بارز
- زرّان كبيران: **افتح الخريطة** و**اتصل بالعميل**

**لتعديل صلاحية موجودة:** غيّر القائمة أمام بريده من موظف إلى مدير أو العكس.
التغيير يسري فوراً على حسابه.

**لإزالة موظف:** اضغط **حذف** أمام بريده — يفقد الوصول فوراً.

> لا تستطيع تغيير صلاحيتك أنت ولا حذف نفسك، حتى لا يبقى النظام بلا مدير.

### تصدير إلى إكسل

زر **تصدير إكسل** ينزّل ملف CSV بكل الطلبات الظاهرة حالياً (يحترم البحث والتصفية
والمدى الزمني). الملف يحمل ترميز UTF-8 BOM فيفتح العربي صحيحاً في Excel مباشرة.

### تتبّع الزوار

الزيارات تُسجَّل في جدول `visits` داخل Supabase — لا بيانات شخصية، فقط معرّف مجهول
ومصدر الزيارة ونوع الجهاز والخطوة. الأرقام تظهر في اللوحة **لحظياً**، بخلاف تقارير
Google Analytics التي تتأخر حتى ٢٤ ساعة (وهي تعمل بالتوازي ولم تُلغَ).

> Google Analytics لا يمكن سحب أرقامه إلى صفحة ثابتة: واجهته تتطلب مصادقة OAuth
> وخادماً وسيطاً. لذلك التتبّع الداخلي هو مصدر أرقام اللوحة.
